## Qualification and failure handling

A launch-blocking integration issue found during review was corrected: the qualifier now records the execution commit that the campaign gate requires. The gate also checks the exact loss contract and the six attempted/completed disposable steps. The failed-qualification path is checked before either main backend or trainer is constructed. The shell launcher exits after a failed qualifier, emits a partial report, and cannot fall through into main training. Cleanup failure also marks qualification failed while preserving its earlier evidence.

The qualifier reuses six representative retained feature sets, checks their identities and the released-state/export equality before model work, preserves the startup/restoration procedure, and records all forward/backward/optimizer work. Synthetic active/inactive/tiny-positive checks are counted once per loss evaluation. A literal-source nonfinite gradient stops before Adam and is retained as a failure; NaN equality is not accepted as parity. CPU zero-probability characterization is evidence of a potential literal-source limitation, not a qualification pass or permission to stabilize the loss.

The additional qualification input-binding issue was repaired during review. The campaign gate now derives the exact nine input paths from the sealed qualification configuration and prepared-feature manifest, requires the same input set as the successful receipt, and rechecks byte counts and digests before constructing a main model. This prevents a valid receipt from a different bundle, or a modified retained feature, from authorizing the current plan. I inspected the repaired gate and independently ran its source/loss/work/input-identity regression together with the failed-qualification-before-native-construction test: both passed under the qualified local interpreter. No pending implementation finding remains from this review.
