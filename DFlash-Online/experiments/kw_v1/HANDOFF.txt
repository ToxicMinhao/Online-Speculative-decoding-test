1. OBJECTIVE AND SCOPE

Test this hypothesis: within K's existing two-response Adam window, learning the relative contribution of each response from its effect on the next ordinary training window improves online adaptation.

Use arm name KW. K's token selection, per-response loss, anchors and model architecture stay exactly qualified. KW adds a five-parameter response-weight controller. The next-window signal is collected training data, not held-out validation, and is not necessarily the next chronological user request because training shuffles within each pass.

This is an algorithm experiment. Complete implementation, the bounded correctness checks below, training and the fixed evaluations. Do not insert a separate normalization study, correction replay, hyperparameter search or fourth training arm. Improvement is a hypothesis, not a required outcome. Generic example reweighting and next-minibatch gradient credit already have prior art; describe this particular optimizer-aware online-SD mechanism without claiming novelty has been established.

3. CONTROLLER: EXACT FEATURES AND DEFAULTS

For each response, use its existing ordinary training forward. Read the detached response loss and additive selection statistics immediately from that response's StepOutput, before TrainerCore merges the two responses' metrics. Do not use the boundary StepResult as if it were one response. Checkpoint recomputation must not create a second observation.

Let:
  W = available_position_weight
  S = selected_position_weight
  H_j = first_error_position_j, j = 1,...,15
  N0 = no_error_blocks
  N = N0 + sum_j H_j
  ell = native response-normalized K loss
  L = full response token count, including EOS when present.

Require finite raw loss, weights, counts and length before any clamp; require nonnegative raw weights/counts and a valid response length. Compute this five-element detached feature vector in FP32:
  z1 = clip(S / (W + 1e-6), 0, 1)
  z2 = [sum_j j*H_j + 16*N0] / (16*N), or 0 if N=0
  z3 = N0 / N, or 0 if N=0
  z4 = max(ell, 0) / [1 + max(ell, 0)]
  z5 = clip(L / 2048, 0, 1).
Clip all features to [0,1] and reject nonfinite values. The no-error sentinel in z2 is 16. Empty blocks contribute to neither N nor its numerator. Clamp the loss only for z4; never alter the native training loss.

Controller:
  phi is a five-vector, initially zero; no bias.
  d_t = z_(t,1) - z_(t,2)
  s_t = dot(phi_entry, d_t)
  a_t = 0.25 * tanh(s_t)
  weights = (0.5 + a_t, 0.5 - a_t)
  b_t = 0.25 * [1 - tanh(s_t)^2] * d_t.

Each response receives weight in [0.25,0.75], with total weight 1. This does not fix gradient norm or Adam step magnitude. Compute controller/scalar operations in CPU FP64 after converting the detached FP32 features; do not consume any training RNG.

Fixed v1 parameters:
  secant half-width delta = 1/16
  credit RMS decay = 0.95
  credit normalization epsilon = 1e-12
  normalized-credit clip = [-1,1]
  controller learning rate = 0.05
  controller L2 coefficient-norm cap = 2.
No tuning against either intermediate or final evaluation results.

4. NATIVE GRADIENT CAPTURE AND EXACT NEUTRAL BEHAVIOR

The pinned TrainerCore backpropagates ell/2 for each response. The response-mean adapter supplies denominator 1 per response, so boundary normalization has scale 2/2 = 1.

Let u1 and u2 be the actual per-response, pre-accumulation backward-hook contributions. They already contain the factor 1/2. Capture each directly; hooks return None and leave native accumulation intact. Never infer u2 by subtracting successive BF16 accumulated .grad buffers.

Let G be the native accumulated and normalized BF16 gradient, before clipping. Preserve it unchanged for the delayed query and for the exact neutral case. Define KW's gradient at allocation a as:
  if a == 0:
      G(a) = G, using the unchanged native path
  otherwise:
      G(a) = BF16( FP32(G)
                   + float32(2*a) * (FP32(u1) - FP32(u2)) ).

Use separate FP32 subtract, multiply and add operations, then one BF16 cast. Do not introduce compiler fusion that changes this numerical contract. Treat a missing response contribution as zero for the perturbation while preserving the native active/None-gradient set. Never turn an all-None parameter into an active zero gradient and thereby change weight decay or Adam state.

This definition applies weighting to stored native gradient contributions. Do not claim bitwise equivalence to weighting losses before backpropagation. Do not rebuild the neutral gradient by averaging newly converted FP32 contributions. Preserve the DDP wrapper, bucket views, trainable-parameter ordering and existing backend normalization.

There are exactly the usual two model forwards/backwards in a training window. No extra backward to form an independently weighted loss or to obtain the next-window query.

5. ACTUAL BF16 OPTIMIZER SECANT AND DELAYED CREDIT

Let T_t(a) be the actual parameter result from applying the qualified optimizer to G(a), starting from the same pre-step weights, Adam moments and counters. It includes native global clipping, BF16 Adam arithmetic, weight decay and BF16 parameter updates.

Form:
  a_plus  = clip(a_t + delta, -0.25, 0.25)
  a_minus = clip(a_t - delta, -0.25, 0.25)
  theta_plus  = T_t(a_plus)
  theta_minus = T_t(a_minus)
  e_t = [FP32(theta_plus) - FP32(theta_minus)]
        / float32(a_plus - a_minus).

Cast each parameter proposal to FP32 BEFORE subtraction. Use the actual clipped denominator, not an unconditional 2*delta. e_t covers the same named trainable parameters as G; store it in FP32.

Both proposals are uncommitted optimizer arithmetic:
- Start each from identical pre-step model/Adam state.
- Preserve native parameter grouping, active-gradient set, optimizer options and foreach/fused dispatch behavior.
- Include the same global clipping rule.
- Never consume RNG, mutate live weights/moments/counters, advance global_step, publish weights or run the model.
- Discard hypothetical moments. Only the real update at a_t changes live model and Adam state.
- Use sequential scratch proposals and reuse buffers where safe. Memory efficiency must preserve numerical equivalence. Never replace this map with a closed-form FP32 Adam approximation followed by a BF16 cast.

At the next window, use h_(t+1) = that window's native G, UNWEIGHTED and UNCLIPPED, to obtain the credit below. A missing current query gradient contributes zero to this dot product, while its optimizer None-gradient semantics remain unchanged:
  c_t = sum_parameters dot(FP64(h_(t+1)), FP64(e_t)).
Perform fixed-order chunked FP64 products/sums (at most 1,048,576 elements per chunk), followed by CPU FP64 accumulation in named-parameter order. This avoids a full-model FP64 buffer.

Positive c means increasing the preceding first-response weight locally predicts increasing the next-window loss. Therefore use gradient DESCENT:
  n <- n + 1
  v <- 0.95*v + 0.05*c_t^2
  v_hat <- v / (1 - 0.95^n)
  c_scaled <- clip(c_t / (sqrt(v_hat) + 1e-12), -1, 1)
  phi <- project_L2_ball_radius_2(
             phi - 0.05*c_scaled*b_t ).

Initially v=0 and n=0. Every scheduled within-pass credit opportunity counts, including c=0. If the proposed controller increment is identically zero (including zero normalized credit), leave phi bitwise unchanged and skip its projection, while still updating the prescribed RMS/count state. Thus an all-zero secant gives exactly zero credit and zero controller change. Cache b_t from the producing window; do not recompute it using newer phi. Reject nonfinite gradients, proposals, secants or controller/credit scalars; never silently replace them with zeros.

This is an approximate first-order loss-transfer signal using a finite secant of a quantized optimizer. It is not an exact derivative through BF16, an exact acceptance/serving objective, or a derivative through future Adam history. Report these limits.

6. WINDOW ORDER, BOUNDARIES AND RESUME

Use this exact order:
1. Cache phi_entry at the start of the window.
2. Run both ordinary unweighted K forwards/backwards; collect per-response features, u1, u2 and native G.
3. Compute and freeze a_t and b_t using phi_entry.
4. If pending eligibility exists from the preceding window in the SAME pass, compute its credit using current G and update phi for SUBSEQUENT windows.
5. Build the two previews from the current pre-step scientific state, obtain e_t, and commit exactly one live native optimizer update using the already-frozen a_t.
6. Save pending (e_t, b_t, producing-step identity), then clear it if this is the predetermined end of the pass.

Thus the first two windows after zero initialization use equal weights; the first learned allocation can occur in window 3. No current-window credit may retroactively change its already-frozen allocation.

Keep phi, v and n across all passes/events. Clear pending eligibility at EVERY pass boundary, in both uninterrupted and resumed execution. There are 64 windows/pass and two passes/event: 126 credit opportunities/event, 504 across this campaign. Generate two previews per window in this first version, including the final window of each pass; its unused eligibility is discarded.

Persist algorithm version, fixed hyperparameters, phi/v/n, counters, model/Adam/RNG, and input/schedule bindings. Complete-event checkpoints have no pending eligibility. Restrict v1 recovery to complete committed event boundaries unless exact mid-pass recovery is implemented and qualified, including saved pass permutation/cursor, pending eligibility/b_t and all RNG/counters. Never silently drop pending credit or reset controller state on a mid-pass restart.
