# Native update-size attribution

This bounded diagnostic asks whether PR47's prefix-withheld one-step endpoint E
beats ordinary native AdamW steps of almost the same realized BF16 size. It does
not implement a new production loss or learning-rate controller.

The caller pins the historical plan, compact archive inventory, public norm and
outcome tables, and current source manifest. CPU `prepare` checks surviving and
missing artifacts, raw outcome provenance, runtime/import identities, exact
boundary norms, and the original serializer on all six surviving P/N/E exports.
A failed serializer copy remains preserved. No missing E model is regenerated.

After that gate, `campaign` runs six disposable native checks and exactly one
unchanged KPLUS6→7 trajectory. At windows8,16,…128 it authenticates P/N and uses
at most ten cached-gradient native Adam applications to bracket E's historical
norm to0.25% per side. Only N continues. All32 logical controls are sealed before
new acceptance scoring. The scorer reconstructs64 parents once, checks24 fixed
P/N/E sentinels and up to8 neutral blocks, and scores up to8192 control blocks.

`analysis` uses the prespecified shared whole-request bootstrap and joint E-versus-
both-controls decision. Local accepted-prefix changes are not serving speedups.
The original BF16 optimizer, loss, masking, anchors and runtime remain unchanged.

Storage accounting starts before CPU reconciliation, includes the staged source,
caches and temporary overlap, and enforces110GB additional allocation plus400GB
free reserve. Existing KEEP and REVIEW artifacts are not cleanup targets. New
control exports may be retired only after full scoring, raw audit and publication.

Hard campaign bounds:294 Adam applications,260 response forwards/backwards each,
8192 main plus32 extra scored endpoint blocks, one A800 and180 occupied minutes.
CPU Gate0 and source staging are timed separately. Failed work remains recorded;
there is no automatic retry or scientific retuning.
