# DFlash baseline learning curve

This screen asks whether ordinary qualified OSD-style training on four fixed
feedback responses improves drafting on four unseen, independent requests. It
separates fitting the feedback, held-out transfer, the effect of more training,
and preliminary serving-time savings. It is not an AdaFlash reproduction or a
new mechanism. PR #8's agreement-filter campaign stays paused.

See [VALIDATION.md](VALIDATION.md) for CPU checks and remaining native checks.

Implementation is submitted for review. **No GPU qualification or experiment
result is claimed in this PR.** Execution requires a separately reviewed source
inventory, prepared sample manifest and explicit `--allow-gpu-execution`.

## Fixed experiment

| Setting | Value |
|---|---|
| Target | Qualified frozen Llama-3.1-8B-Instruct |
| Draft | Released UltraChat DFlash; same 58 backbone parameters as qualified ordinary OSD |
| Frozen components | Target, draft token embedding and vocabulary head |
| Training | Forward KL, temperature 1; AdamW LR `3e-4`, betas `(0.9,0.999)`, epsilon `1e-8`, weight decay `0.01`; clip global gradient norm at 1 |
| Accumulation | Microbatch one response; average two **separately normalized** response losses, then clip and step once |
| Checkpoints | Step 0 (released), step 2 (one pass), step 8 (four total passes) |
| Serving | Greedy, concurrency 1, block size 10, 1,024 output tokens or EOS |
| Context | 32,768 total; full input + 1,024 output + 9 proposal positions must fit; effective maximum input 31,735 |
| Cache policy | Flush before each independent request and weight switch; qualified native publication refreshes helpers |
| Seeds | Selection `20261020`; reset draft/optimizer and training seed `17` per group |

The qualified author sampler, target conditioning, position weighting and
within-response reduction are imported unchanged. Responses are never joined.
Only each generated answer receives loss; its own prompt remains context. No
agreement filter, reverse KL, adaptive length head, alternative optimizer or
precision change is introduced. `donated_buffer=False` retains the qualified
compiler policy.

Six independent groups: two each from GSM8K, CodeAlpaca and ShareGPT. Each group
has four feedback prompts and four held-out prompts, all 48 globally distinct.
All four feedback answers are generated by the **frozen draft before training**;
no additional answers replace them at later checkpoints. The eight optimizer
steps continue on the same draft, optimizer and sampler state. Step 8 is six
additional steps after step 2.

Source-loss diagnostics use their own fixed sampled anchors at steps 0/2/8,
with training/global RNG and module modes preserved. Their time is separately
reported; they generate no new answers. Normal training keeps normal per-pass
anchor sampling. Exact anchors, masks, denominators and actual supervised
position counts are retained for every presentation. The qualified sampler can
produce zero-supervision samples on very short answers; those are explicitly
recorded and retain the ordinary scheduled optimizer step, without resampling.

## Reproducible data preparation

`dataset_sources.json` pins actual upstream revisions, files, byte counts,
SHA256s, preprocessing, split policy, language heuristic and selection order.
Sources follow the pinned author's dataset repositories. GSM8K uses official
train/test splits. CodeAlpaca uses disjoint prompt partitions; nonempty `input`
fields are retained along with `instruction` (an explicit adaptation from the
author's instruction-only normalizer). ShareGPT uses disjoint conversations,
English text and only the first user message. Recorded answers are unused.

Selection is CPU-only, requires the exact local source files and qualified
local tokenizer, and never downloads data or loads a model. The manifest is
sealed before generation. Full selected wording, including whitespace, is
re-encoded and checked at launch. Exclusions, overlap checks and shortfalls are
recorded rather than replacing samples based on model behavior. Raw datasets,
selected text, token streams and runtime artifacts stay outside this checkout.

The separate CPU preparation environment uses `requirements-data.txt` (not the
qualified GPU environment). Preparation requires `langdetect==1.0.9`; missing
dependencies fail explicitly.

See `python -m experiments.dflash_baseline_learning_curve.data --help` for the
local-file preparation command. Source bindings map the four named source keys
in `dataset_sources.json` to local artifact paths. A prepared manifest is a
required input to planning and execution; this code review does not claim that
the 48 actual prompts have already been selected.

## Evaluation and correctness gates

After training through step 8, the controller terminates the **entire training
process group** and confirms that no trainer/teacher child remains. Before every
timed request it checks quiescence again. No background training is allowed,
even on the other GPU. Separate timers alone are not accepted as isolation.

Each checkpoint receives one explicit synthetic warmup per group, outside
scoring. Checkpoint order rotates across the four held-out requests. All three
checkpoints receive identical input token IDs. Their greedy outputs are compared
token-for-token with frozen, including when frozen runs last in the rotation.
Raw rows are durably saved before validation. Mismatches, nonfinite values,
unreproducible bindings or invalid accounting stop the affected run and preserve
its evidence. Correctness is checked again by reporting.

The first complete group is **one of the six**, not an extra qualification
trajectory. If its execution checks pass, the runner continues to the other five
automatically. Null or harmful adaptation never blocks continuation or changes
settings.

| Planned work | Count |
|---|---:|
| Frozen feedback generations | 24 |
| Held-out generations: 6 groups × 4 prompts × 3 checkpoints | 72 |
| Core generations | 96 |
| Optimizer steps | 48 |
| Training response presentations | 96 |
| Explicit synthetic warmup generations, excluded from gains | 18 |
| Source-loss response forwards, no generation | 72 |

Engine initialization/compilation and any internal startup warmup are recorded
as startup work, not core generations or scored timing.

## Metrics and cost boundaries

- Complete request latency includes native prefill, drafting and target
  verification, with feedback capture disabled. Publication, cache flush,
  training, diagnostics and warmup are outside that request timer.
- Accepted draft tokens exclude corrections/bonuses. Verification-committed
  progress includes them, and excludes the initial target-prefill token. Total
  emitted tokens per call additionally includes that initial token. Both are
  reported with explicit names; zero-call EOS cases have undefined ratios.
- Per-round records retain output offsets, correct proposed-prefix lengths,
  first rejection offsets, accepted/committed counts and EOS/cap clipping.
- Teacher preparation is a **nested component of training time**, not added
  twice. Draft training, fixed-anchor diagnostics, export, optimizer persistence,
  loading/activation, cache maintenance, startup, shutdown and peak memory are
  retained separately. Activation times the complete worker publication call;
  the native publication timer is nested evidence.
- One timing observation per checkpoint/request is preliminary. Group/domain
  ratios use summed paired measurements, never an average of percentages.
  Source-loss reduction does not establish held-out improvement. Serving-only
  savings with an available checkpoint are not net online acceleration.

## Review and execution commands

Run from the repository root, with outputs outside Git:

```bash
python -m pytest -q experiments/dflash_baseline_learning_curve
python -m experiments.dflash_baseline_learning_curve.run plan \
  --manifest /absolute/private/data/MANIFEST.json \
  --out /absolute/private/review_plan
```

After code/data review and execution authorization, adapt
`runtime_config.example.json` to the qualified installation. Source the approved
A800 environment helper and use the qualified Python environment. Do not copy
private credentials or responses into Git.

```bash
python -m experiments.dflash_baseline_learning_curve.run run \
  --manifest /absolute/private/data/MANIFEST.json \
  --tokenizer /absolute/pinned/tokenizer \
  --runtime-config /absolute/private/runtime_config.json \
  --reviewed-code-sha256 CODE_HASH_FROM_PLAN \
  --reviewed-manifest-sha256 MANIFEST_HASH_FROM_PLAN \
  --allow-gpu-execution \
  --out /absolute/private/fresh_run
```

The runtime refuses incompatible source/model/data bindings. Its storage
preflight budgets all six groups' retained exports and optimizer states, plus
staging and an 8 GiB reserve. It does not delete historical artifacts or silently
retire checkpoints to fit. Storage/offload must be prepared before a GPU launch.

## Deliverables

The private run writes source/config/sample bindings, exact commands and commit,
raw event rows, all input/output IDs, native trajectories, per-step training
records, fixed-anchor source losses, exports and optimizer/RNG state. Reporting
writes `REPORT.md`, per-request/per-round tables and group/domain comparisons,
including invalid rows, unfinished groups, nulls and regressions. The report
answers source fit, held-out transfer, step-8 versus step-2 improvement, calls
versus latency, and training cost separately. It stops at this bounded screen.
